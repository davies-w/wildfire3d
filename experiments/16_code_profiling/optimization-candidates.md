# Candidates supported by the first lot profile

This file distinguishes observed cost from untested source edits. No source patch has been benchmarked yet. Measurements refer to a 30-second early lot exposure, not a validated full ignition scenario.

| Candidate | Evidence | Test or verification required | Limit |
|---|---|---|---|
| Reduce waiting CPU with passive OpenMP policy | 43.07% of CPU samples in libgomp; 27.32% have no FDS caller in captured stack | Same four threads, identical deck, OS CPU and wall time, compare every device/boundary output | CPU savings can differ from elapsed-time/cloud-cost savings; removing all runtime cost still gives only 1.76× at fixed remaining work |
| Serial path for small wall-adjacent face reconstruction | libgomp samples associated with divg/mass wall-loop callers; GET_SCALAR_FACE_VALUE uses a serialized parallel region for small stencils | Add a serial branch preserving the exact limiter arithmetic; test all limiter/orientation/boundary cases before runtime claims | Cannot remove full transport cost; caller stacks and source lines do not establish a 10× opportunity |
| Retain radiation parallel team/cache geometric slice lists | radi.f90 repeatedly enumerates diagonal slices and enters parallel regions | Preserve wavefront dependency barriers; compare intensities, heat flux, energy, and ignition outcomes | Radiation is only 8.8% of wall-timer work in this early exposure; hot-exposure exclusive radiation leaf is likewise approximately 4.2% of sampled CPU |
| Reuse/fuse gas-property and transport calculations | Highest FDS leaves include scalar face values, species advection, and enthalpy interpolation | Audit predictor/corrector cache invalidation and species conservation; measure memory traffic with appropriate counters later | Thermodynamic tables already exist; no measured memory-bandwidth claim |
| Coarsen or localize CFD resolution | Explicit grid work plus timestep count dominates multiple routines | Compare wall temperatures/fluxes, physical geometry after snapping, and long-horizon ignition across cases | Potentially much larger savings, but changes the numerical approximation; short-window agreement is insufficient |

Baseline repeatability: 1252.110 and 1230.338 CPU-seconds, 345.706 and 339.137 elapsed seconds. Recorded device curves are identical. The profiled run used 1234.218 CPU-seconds and 340.479 elapsed seconds, within this observed spread; profiler overhead is not separately resolved at that precision.

Tenfold acceleration requires eliminating about 90% of baseline cost. Exclusive FDS samples are spread across many functions (largest approximately 4%). The evidence currently argues against a single simple function rewrite delivering that reduction. This does not prove that a different algorithm or a carefully validated model reduction cannot achieve it.

Measured passive-wait test: 799.31 CPU-seconds versus 1193.67 baseline (33.0% less; 1.493x CPU speedup). Elapsed 335.69 versus 331.89 seconds (1.1% slower). Recorded device curves match exactly; west-face 20–30 s boundary range is 20.379–237.920 C in both. This supports avoiding wasteful busy waiting, but does not establish cheaper elapsed VM time or a tenfold route. Other model settings remain unchanged.

Measured approximation screens: reduced radiation costs 1152.96 CPU-seconds versus 1193.67 (1.035x), with maximum wall/roof-device differences 28.99/26.40 C. Uniform 1 m coarsening costs 98.43 CPU-seconds (12.127x), but wall/roof differences are 103.31/65.80 C and the ignition threshold changes outcome (23.0237 s coarse; no event in 30 s baseline). Raw west-face burning rate corroborates that difference. Neither screen establishes an acceptable high-fidelity 10x optimization.

The passive run incurred 7,457,739 voluntary context switches versus 12,866 in the hot baseline. User CPU fell from 1152.63 to 741.17 s, while system CPU rose from 41.04 to 58.14 s. This is consistent with replacing active waiting by frequent sleeps/wakeups, and strengthens the case for measuring the cost of repeated parallel regions. It does not locate all those switches or prove a particular source patch will help.

The coarse case used 612 timesteps versus 1372 baseline and one eighth as many cells. A simple cell-times-step count falls 17.93x, whereas measured CPU falls 12.13x; fixed work, changed geometry/physics, and runtime overhead prevent treating ideal grid scaling as a performance prediction.

The longer profile confirms the distribution (44.03% OpenMP, largest FDS leaf 4.12%). Early-positive termination is available through existing FDS controls and should be enabled when producing binary labels, but this case still consumes 143.41 CPU-minutes before its first threshold event. The next evidence-based experiments are (1) a source patch avoiding tiny nested/serialized parallel-region setup, with arithmetic-preserving tests and paired full-output checks, and (2) geometry-preserving selective refinement, with explicit clearance/overhang checks and long-horizon ignition comparisons. Neither is implemented or claimed to deliver 10x. A CPU-targeted compiler build is another unmeasured smaller candidate. No additional paid trials were launched.
